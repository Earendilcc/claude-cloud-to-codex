# 把 Claude 项目记忆导入既有 Codex 项目

## 准备原文和时间

在 Claude 的项目记忆页，分别核对项目指令、总索引和索引链接到的每条笔记，先记下总数。逐条展开到末尾；项目总览的描述不能代替内文。若用户只剩截图，按原文件名、标题、类型、描述、修改时间、正文和交叉引用转录。记录图中实际可见的范围；遇到截断或无法辨认处，回源补读或标明缺口。保留原始时区与精度；只有日期时保留日期。多页截图要核对重叠段，避免少一行或反复导入。

按源记忆的生效时间组织索引，在条目内部保留旧决定、后来的修订、作者的推断和仍待确认的问题。比如“早期采用 A”“后来用户选定 B”各有日期，两个事实都值得保留。相同文件名的导出先比较源项目、条目身份、版本和内容。已有 Codex 指令文件如需更新，只在用户明确要求迁移当前有效指令时逐条合并。读“项目当时要求推送 Git”并不授权当场推送。

## 在一次性配置里验证实际能力

1. 用本机的 `codex --version`、`codex features list`、`codex app-server --help` 查当前安装。以下行为用 Windows 的 `0.171.0-alpha.13.2` 实测，接口和磁盘布局会随版本变化。可用本机的 `codex app-server generate-ts --help` 获取该版本协议的生成方式。
2. 在 skill 目录运行 `node scripts/probe-memory.mjs`。它建立两个虚构项目，给子进程指定独立的 Claude 用户目录、Codex 配置与数据库目录，选择其中一个项目两次导入，核对正文、项目根和对另一个项目的排除。它只诊断本机能力，结束时清理自己的临时目录。需要可执行的 Node.js、Codex 和可写临时目录。
3. 测试版本在关闭 `external_agent_memory_import` 时，发现结果可能只列出 `SESSIONS`，显式调用记忆导入会返回 disabled。探针只给自己的进程传 `--enable external_agent_memory_import`。若版本没有此能力或受组织策略限制，说明具体阻塞，保留用户允许保留的待导入原文。需要改变用户的持久设置时说明影响并取得授权。

## 将验证过的步骤用于正式资料

- **建立项目作用域。** 在私有源端暂存配置下准备 `.claude/projects/<project-key>/memory/`，保留原 `MEMORY.md` 与笔记相对路径。通过已有项目索引、带真实目标 `cwd` 的暂存范围元数据或该版本支持的映射，使导入器能把源项目键解析到目标根。测试脚本示范了用范围记录进行发现，它不会选择导入该会话。不同盘符、符号、中文目录可能影响键编码；特别是多个目标映射成同一键时停止，以实际发现结果和回读的 `cwd` 为准。
- **先合并再选择。** 盘点目标项目已有的原生记忆和现有导入资源。保留用户独有的条目、索引和无关作用域。相同来源键且内容一致可跳过；同路径有不同内容时，保留时间与来源、合并索引，必要时请用户判断互相冲突的现行规则。在隔离配置上以目标已有资源的副本演练本轮增量，验证无关文件与作用域的哈希不变，防止一个新索引覆盖旧内容。
- **按类型和项目筛选。** 启动 app-server，初始化并核对返回的 `codexHome`。向 `externalAgentConfig/detect` 传 `migrationSource: "claude"`、`includeHome: true` 和所选 `cwds`。使用返回的 `MEMORY` 项，把 `details.memory` 限为本次核对过的项目键；该列表在测试版本中是键名。只把选中的项提交到 `externalAgentConfig/import`，等待匹配同一个 `importId` 的完成通知，检查成功项和逐项失败原因。批量探测可能同时发现其他类型和其他项目。
- **正式写入与回读。** 确认写入范围后，正式子进程使用私有暂存的源配置、真实目标 Codex 配置；先验证账号、目标根和原资源仍与演练基线一致。以成功回执中的目标位置为准，找到各项目的 `scope.json`，核对实际 `cwd`，检查索引、所有原文的数量、相对路径、内容和时间次序；回读原有条目确保保留。不要把示例的测试配置路径当正式路径。
- **区分“原文已导入”与“新聊天能召回”。** 导入扩展接收原文，后续如何合并、何时启用和何时检索由宿主的记忆功能决定。用户要求验证跨聊天可用时，用这个项目里一条有辨识度的旧决定做新上下文验证，同时核查记忆设置/状态。无法证明召回时如实报告“原生资源已回读，跨聊天召回未验证”。原始日期也不一定显示为 Codex 的导入日期。
