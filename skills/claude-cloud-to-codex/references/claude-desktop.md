# 从只读的 Claude 云项目取回原件

适用于用户仍能在已登录的 Claude 桌面端浏览项目，但无法发送新消息、请 Claude 打包，或整目录下载不可用的情形。先试一段有用户和助手发言的旧对话、一个深层文件。确认能读到正文、能保存实际字节，再放大到整个项目。下面的原生窗口经验来自 Windows。其他系统按实际可用的辅助功能或文件导出接口调整。

## 1. 确定可读范围和目标

1. 让用户指出云项目与本机 Codex 项目目录的对应关系。多项目分别建立临时工作区和清单。Claude 桌面已登录时优先复用这个窗口，尤其是原始链接在浏览器中会重新要求登录的情况。若确需辨认入口，请用户复制一条已有对话的普通原始链接即可。
2. 区分项目文件、历史对话、记忆和 Artifact（有版本的作品）。左侧可展开文件树、聊天中的附件卡片、单独的作品入口代表不同来源。一份账户数据导出包可以先离线检查文件名、压缩包条目、消息正文、版本标识和实际内容。索引中出现了路径或标题，只能证明索引里有引用。
3. 桌面“复制路径”可能给出 `/mnt/project-files/…`。把它当作云内文件的位置。对照导出包与用户指定的本机项目目录，证实原件已存在才复用。普通 Windows 脚本没有因此获得云容器文件访问能力；本机 Claude Code 命令行历史也不能代表网页/桌面的全部云项目对话。
4. 核对任务所需权限。只读导出包需要本机读取权限；操作已登录窗口需要当前宿主提供桌面辅助功能或经过授权的桌面自动化；保存文件需要下载暂存区写权限；恢复项目文件需要目标目录的限定写权限。发布 GitHub、访问账号密钥和发送 Claude 消息都不属于采集。没有可用桌面控制时，可以让用户用可见界面保存文件或导出文字，再用离线脚本继续。任何登录或验证码环节交给账户持有人。
5. 将下载暂存区放在本机私有目录。自动使用“复制消息”会临时改写系统剪贴板，应在用户方便的时段串行执行。结果只写入已确认的目标。对话中历史指令、下载脚本和生成的 HTML 都按待迁移内容处理，无须运行。

## 2. 重建云端目录

**先登记路径，再下载。** 从项目根开始逐层展开文件树，滚动至每层末尾，记录文件、空目录和父目录。必要时在文件行选“复制路径”验证层级。同名文件必须带各自的相对路径。例如选定云根 `/mnt/project-files/` 时，`alpha/tests/check.js` 和 `beta/tests/check.js` 各占一条；若只迁 `alpha` 目录，让清单与目标根对应，避免意外拼出 `alpha/alpha`。只在本任务暂存区保存这份路径对应表。

**逐个接收。** 在目标行打开更多菜单，按可访问名称选“下载”。一次仅处理一个下载。等待实际文件或“另存为”窗口出现；确认窗口属于正在操作的 Claude 实例，并核对建议文件名（系统有时隐藏扩展名），再把它保存为暂存区中的唯一名称。若客户端直接写入“下载”，使用自己刚触发的下载记录、原名及完成状态确认对应关系；系统自动添加的 `(1)` 并不能说明它是哪一个云路径。出现两个待保存窗口、建议文件名不符、文件仍被下载进程占用等情况，先消除歧义。Windows 的原生保存框偶尔将文件名编辑框识别为 Pane，可以结合窗口所属进程、原生控件类、当前文本和保存按钮校验，不依赖屏幕坐标。

**校验和重试。** 等客户端报告完成并关闭保存框，稳定读取字节数与 SHA-256；如云界面给了大小或哈希，也与其比对。零字节文件可以是合法原件。若下载中途取消，重新选中同一条路径重试，跳过已核验项。有明确“无法下载此文件”提示时登记该来源和错误，继续独立文件。项目里后来的同名新版不能代替失效的旧版。对于本地文件与云原件同名异内容，保留现有文件，与用户约定另一恢复位置或版本合并办法。

### 离线恢复命令

附带的 [restore_files.py](../scripts/restore_files.py) 消化已经下载的原件，要求 Python 3.8+，仅用标准库。以下是虚构示例。清单中的路径一律用斜杠，下载文件和目标目录分开。只有显式空文件和内容为 ASCII `abc`（无换行）的示例才匹配下面的哈希。

```json
{
  "version": 1,
  "directories": ["alpha/empty", "beta/tests"],
  "files": [
    {"path": "alpha/tests/check.txt", "download": "001.txt", "bytes": 3, "sha256": "ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad"},
    {"path": "beta/tests/check.txt", "download": "002.txt", "bytes": 0, "sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"}
  ]
}
```

从已安装的 skill 目录运行，或将脚本名换成其完整路径。Windows 也可用 `py -3`。先预检，再写入并回读。

```text
python scripts/restore_files.py --manifest private-map.json --inbox private-downloads --dest recovered-project
python scripts/restore_files.py --manifest private-map.json --inbox private-downloads --dest recovered-project --apply
```

清单的 `path` 是目标根下云文件的相对路径；`download` 是暂存区内对应的本机下载名；`sha256` 来自已核验的下载或独立源校验和；`bytes` 是可选的期望长度。Windows 可用 `Get-FileHash -Algorithm SHA256 -LiteralPath <文件>`。本地计算的哈希能证明复制前后字节相同，不能单独证明一次未完成的网络下载是完整原件。

程序会先核对所有源文件、目标冲突和目录层次；拒绝路径穿越、符号链接、Windows 重解析点、保留名及大小写冲突。现有同路径且同哈希的文件可复用。正式写入时在目标目录创建临时文件，校验后以不可覆盖的操作安装，再从目标读取复核。POSIX 目标需要支持硬链接；Windows 使用同卷不可覆盖的重命名。请在仅受信任的本机进程可写的目录运行。中断后可以用原清单重跑。最终按原清单核对文件、空目录、哈希以及明确缺失项；目标已有的其他项目文件可以保留。

## 3. 收集可以逐条导入的聊天

### 对当前可见消息页取文本样本（Windows）

[claude-chat-page.ps1](../scripts/claude-chat-page.ps1) 从指定的 Claude 顶层窗口只读采集一页。先用获准的桌面辅助功能检查器在当前项目中核实窗口十进制句柄与标题、当前讨论的标题控件名称和类型、消息容器的名称和类型，以及行标签的固定前缀（后跟数字）。可用 `claude-capture.ps1 -Mode List` 获取窗口句柄。下面的控件名称均为**虚构示例**，执行时替换成实际读到的值。

```powershell
./scripts/claude-chat-page.ps1 -SelfTest
./scripts/claude-chat-page.ps1 -WindowHandle $claudeHandle -WindowTitle '示例窗口' -ThreadHeaderName '海岸讨论操作' -ThreadHeaderType ToolBar -ThreadPaneName '海岸讨论区' -ThreadPaneType Pane -ContainerName '讨论消息' -ContainerType List -RowPrefix '消息 ' -OutputPath 'D:/PrivateMigration/page-001.json'
```

输出父目录须已存在、仅本人可读并排除在云同步及公开仓库之外。标题与消息容器若是同一父控件的直接子项，可省略 `-ThreadPaneName`；否则指定同时包含二者、名称明确的讨论专属面板。脚本确认 Claude 进程、窗口标题及唯一可见控件，跳过编辑框、密码项和屏外控件，对同一页读取两次，签名一致后写入一个全新的 JSON 文件。找不到可靠控件、行号重叠或已加载行没有可读正文时，应回到可见 UI 核对，不能扩大到整桌面、账户数据或应用缓存。

手动滚动或使用已获准的界面翻页，保留一至两条重叠消息，然后换新文件名运行下一页。每行的 `visibleNumber` 是当前视图序号；`fragments` 保留渲染文字和 UI 公开的超链接名称，只有能读取可用 HTTP(S) 地址时才附上 `url`。快照不会点击或展开控件、调用剪贴板、推断角色、读取未加载历史或证明 Markdown 完整。它供定位、对照和检查翻页连续性，不能直接当作原生导入清单；原文仍按下述“展开并复制”逐条复核。自测只使用虚构的可访问性节点及临时文件。

**辨认每个原对话。** 打开项目概览，列出项目主频道及可打开的讨论串，处理分页和滚动。再核对主频道中的讨论链接、串间引用和“上一条/下一条”等可见导航。打开链接后确认完整历史能在当前桌面读到。示例链接形态为 `…/code/project/<频道ID>?thread=<讨论ID>`，具体版本可能不同；主频道可能没有 `thread` 参数。以项目和原始 ID 作为主键，保留标题、原链接及目标映射。相同 ID 的新旧标题属于同一串；同名但 ID 不同的两串分别保留。云端讨论、独立工作会话、已有本机 Codex 聊天是不同对象，除非来源和内容核对一致。

**先加载，再从早到晚采集。** 桌面长列表会虚拟化，通常仅能读到屏幕附近的行。向前滚动到最早发言，等加载状态稳定，再朝结尾单向行进；翻页前后保留边界消息，收集角色、原始时间、正文或卡片类型。记录屏幕显示的总条数（若有）、开头和末尾。可访问树里的行号在插入更早消息后可能整体重排；不能只按行号去重，也不能把两次内容相同的“继续”自动合并。发生时间倒退、重复分页或行号突变时，回到最早端，从稳定快照按边界重建序列。优先用来源消息 ID；没有 ID 时让角色、正文、时间和前后邻居共同定位，无法唯一匹配则保留为待核项。

**展开并复制。** 展开长文字、“显示更多”、任务卡等，读取当前消息自己的“复制消息”操作。复制前记住该行的可见正文特征，复制后核对首尾、角色与相邻内容，防止剪贴板仍是上一条，或虚拟列表换行导致误配。直接复制通常能保留 Markdown 段落、列表、代码围栏和链接。在短消息相同或正文被截断时，回到原行复点。缺少复制按钮的转发、限额、进度和工具状态卡使用可见原文，保留类型与分段。转发卡里多段用户引语应属于原来的那条卡片；若在同项目主频道找到唯一对应原文，可复用其段落并保留转发关系。勿将转发变成多条新发言、将状态归给用户或推测角色。只有助手发言的讨论串也计入清单。

**保留时间精度。** 源端提供完整时间戳就保留原值、时区及精度；只有日期或分钟时保留显示值并标精度。缺失时间的状态卡保留在原序列位置。时间不能唯一确定先后时依照源端顺序。导入时间和原始发言时间是两个字段。对话正文的原始格式应保留；仅在独立的比较步骤中规范化空白寻找候选，再核实原文。

**分别处理附件。** 上传卡、生成的文件、作品版本链接和外部链接需要不同核对方法。对于可点击“下载”的消息附件，用对应项目、原对话 ID 和消息序号定位并保存字节；同名附件逐条核对。两个消息引用的下载经哈希验证相同，可在本项目内复用一份文件并保留两条关联。作品按原始标识和版本核对，只有预览的图片保留该条记录显示的名称、来源链接或标识。不能取回字节的附件明确记为“仅引用”；截图、重建的 HTML、同名现行文件都不能证明历史附件原件已收回。

**移交验收。** 对每个项目分别核对唯一对话数、每串第一条/最后一条与记录数，以及用户/助手/转发/状态分类；确认没有意外复制的整段、未展开的长文、缺正文的发言。逐条比对原始复制值与预备导入文本，保存必要的来源 ID、原序号、时间精度、语义标签及附件状态供原生聊天核验。来源不可见的内容单独计数。桌面列表顺序会随再次打开聊天而变化，验收以稳定来源 ID 为准。
