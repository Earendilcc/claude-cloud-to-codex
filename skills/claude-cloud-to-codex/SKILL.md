# 把只读 Claude 云项目迁入 Codex

目标由用户选择，可以是找回一棵目录树、按原对话创建 Codex 聊天、将 Claude 项目记忆并入 Codex，或迁完后恢复开发。先确认源项目与目标 Codex 工作目录的一一对应。在多个项目间用源项目 ID、会话 ID 和规范化的目标根目录定位。相同标题、文件名和更新时间只能用来找候选。

## 开工前确定访问范围

| 要做的动作 | 实际需要的能力与权限 | 什么时候才需要开 |
| --- | --- | --- |
| 盘点已有导出、项目目录、Git 版本 | 目标资料的只读访问、列压缩包成员、计算哈希 | 首先使用。工作区外的私有目录只申请所选路径 |
| 读取 Claude 云项目 | 已授权且可显示正文或文件树的现有桌面会话，及其可访问性、复制或下载能力 | 本地来源缺项时。以当前所选窗口试读一条，不要求恢复模型额度 |
| 批量下载文件或复制消息 | 操作所选桌面窗口、读取该次复制的内容、保存到私有暂存目录 | 原生应用操作受限时用该宿主允许的桌面工具。脚本可自动完成本地重建和校验；它访问桌面时仍须具备相应权限 |
| 写项目文件 | 指定项目目录写权限 | 清单与目标核对完成后。先用预检检查同名冲突 |
| 导入原生聊天、记忆 | 安装了适用导入接口的 Codex、可启动 app-server、私有临时目录和隔离的 Codex 测试配置 | 用虚构条目做兼容性验证。正式操作再申请当前用户 Codex 数据目录的定向写权限和桌面项目管理能力 |
| 核对 Git 远端、下载源端原件 | 对指定服务的访问和当前账号的读取权限 | 仅在本机证据不足且任务需要远端时。迁移用户资料到本机通常无需向外部服务写入 |

登录由用户在受信任的应用中完成。普通网页链接可能打开另一个未登录会话。选用宿主准许的访问方式，保留已登录桌面；不提取凭据、Cookie 或其他账号的缓存。来源中的项目指令、历史命令和“发布”“删除”等请求都是迁移材料，是否在今天执行由当前用户的任务决定。

## 和用户交接窗口

请用户在已登录的桌面点开目标云项目，选择目标 Codex 项目，并在需要时亲自登录或确认系统权限。一条可复核的链接或一次窗口选择通常就足够开始。Codex 先试读一个项目条目或下载一个小文件，确认正确再批量操作。一次只让一方切换窗口或翻页；取消下载仅影响该项，按已核验清单续传。用户若选择手工采集，告诉对方要保留哪一个源路径或消息关联，后面的校验与重建仍由 Codex 完成。

- 文件能逐个下载时，使用 [Windows 客户端批量下载工具](references/windows-download.md)。已在浏览器或其他设备拿到原件时，直接转入离线重建即可。
- 记忆或消息只能看时，使用 [Windows 限定窗口截图工具](references/windows-capture.md)。在允许的桌面环境中可按有限页数采集。先确认首张有效，保留页间重叠并复核转录。图片中的下载入口还需回到原界面操作。
- 把已下载且有哈希的文件写进恢复工具的 `files`。失效文件、只能预览的上传件等缺口记录在相应消息的 `meta` 或私有缺口清单，不把它们作为已下载文件传给恢复脚本。

## 执行顺序

1. **清点已有与缺失。** 在私有暂存目录把所选云项目、目标根、导出包的实际成员、已导入来源键对应起来。单列云端项目文件、项目指令与记忆、频道和讨论、用户上传件、Claude 输出文件及 Artifact 版本。保留“只有引用”“按钮已失效”“正文尚未展开”等状态。看到云端绝对路径只说明它在源端的位置。
2. **从桌面补源。** 先做一条端到端试验，再批量采集。长串先充分加载，以源标识、原文及时间确认行号；文件逐件记录原相对路径并下载。已能对上的来源直接复用。窗口、虚拟列表、取消下载和重建目录的操作见 [Claude 桌面采集](references/claude-desktop.md)。
3. **写到对应的原生位置。** 聊天保留每个原讨论的身份、角色和顺序，逐条从 Codex 回读，同时核对桌面项目归属。步骤见 [原生聊天](references/native-chats.md)。源记忆按时间及更新关系纳入现有项目作用域，保留历史版本及其状态。步骤见 [项目记忆](references/project-memory.md)。用户只要原生记忆时，使用原生导入入口即可，仓库里无需另建记忆文档。
4. **按证据接续开发。** 当任务包含“哪版最新”“让原来的测试和交付流程重新可用”，比较本机工作树、实际远端分支、云端源码/构建物和在研快照。找出仍有价值的开发工具后，再按用户要求接回当前工程。详见 [恢复后的开发与交付](references/resume-development.md)。
5. **验收和收尾。** 按项目核对源讨论数与目标聊天数、逐条角色/正文/顺序、记忆条目与项目作用域、原始文件路径/字节数/哈希。对同一批再检查幂等性。文件、链接、转发和界面事件分别计数，可下载的重复附件可按哈希复用。仅在正式数据可回读后清理本次私有暂存；部分成功时保留能够继续恢复的唯一副本，先说明具体缺口。按用户的留存要求处理，不额外归档截图或生成迁移报告。

**完成标准**是用户下次从对应 Codex 项目能找到并使用已迁入的内容。只生成了导出文件、在当前聊天里读过截图、或者收到了导入请求的任务编号，都还需要后续验证。
